Section 1

Graphical Method

What it is

Solves Linear Programs (LPs) with exactly 2 decision variables (X1, X2) by plotting constraints as lines on a 2-D plane, identifying the feasible region, and evaluating the objective at each corner point. Includes an automatic text extractor: paste a textbook problem and the system fills the form for you.

When to use it

  • Your LP has exactly 2 decision variables.
  • You want a visual, geometric understanding of the solution.
  • As a teaching tool — before moving to multi-variable Simplex.

System limits

Variables
Exactly 2 (X1, X2)
Constraints
Up to 12
Types
≤, ≥ or =
Coefficient range
−10⁹ to +10⁹

Accepted formats: 3 · 3.5 · 1/3 · -2/5

How to enter data

1

Select Maximize or Minimize.

2

Enter coefficients C1 and C2 for Z = C1·X1 + C2·X2.

3

For each constraint: coefficient of X1, coefficient of X2, operator (≤/≥/=), and right-hand side (RHS).

4

Click Solve. Alternative: paste the problem text in the extractor → click Extract → review → Solve.

What the result displays

  • Interactive 2-D graph: constraint lines, shaded feasible region, labeled vertices, highlighted optimum.
  • Table of all corner points with their Z values.
  • Optimal coordinates (X1*, X2*) and Z*.
  • Iso-profit/iso-cost line showing the direction of improvement.

Special cases

Infeasible

Feasible region is empty (contradictory constraints). No shaded area on the graph.

Unbounded

Feasible region extends to infinity in the optimization direction. App reports "Problem is unbounded."

Multiple optima

Objective line is parallel to an active constraint. App shows both extreme points of the optimal edge.

Quick example

🧪 Example
Maximize  Z = 5X1 + 4X2
Subject to:
  6X1 + 4X2 ≤ 24
   X1 + 2X2 ≤ 6
  X1, X2 ≥ 0

➜ C1=5, C2=4 · R1: 6, 4, ≤, 24 · R2: 1, 2, ≤, 6
✔ Expected result: Z* = 21  at  (3, 1.5)

Section 2

Simplex Method

What it is

The Simplex Algorithm moves through vertices of the feasible polytope, improving the objective at each pivot, until reaching the optimum. This implementation uses exact rational arithmetic and provides a full Sensitivity Analysis report. Variables can have optional names and units for readable output.

When to use it

  • Your LP has more than 2 variables.
  • All constraints are ≤ (less-than-or-equal).
  • You need sensitivity / post-optimality analysis.

System limits

Variables
Up to 10
Constraints
Up to 12
Types
≤ ONLY
Anti-cycling
Bland's Rule (after 50 iters)

How to enter data

1

Select Maximize / Minimize and set the number of variables (1–10) and constraints (1–12).

2

(Optional) Assign a name and unit to each variable.

3

Enter objective function coefficients.

4

For each constraint: enter coefficients and RHS value (all ≤).

5

Click Solve.

What the result displays

  • Initial tableau and each iteration tableau with pivot highlighted.
  • Entering and leaving variable per iteration.
  • Optimal solution: each variable value and Z*.
  • Sensitivity Analysis: optimality ranges for Cj, feasibility ranges for bi, shadow prices.

Special cases

Infeasible

Detected if no feasible starting point exists (e.g., negative RHS). Rare with ≤-only problems.

Unbounded

No valid pivot row in some iteration. Solver reports unboundedness.

Degeneracy

Basic variable with value 0. Bland's Rule prevents cycling automatically.

Multiple optima

Non-basic variable with zero reduced cost in the final tableau.

Quick example

🧪 Example
Maximize  Z = 3X1 + 5X2
Subject to:
  X1       ≤ 4
  2X2      ≤ 12
  3X1+5X2  ≤ 25

➜ Variables: 2 · Constraints: 3
✔ Expected: X1=0, X2=5, Z=25
⚖️
Section 3

Two-Phase Method

What it is

Handles LPs with ≥ or = constraints by running two simplex passes. Phase I: minimize the sum of artificial variables to find a basic feasible solution. Phase II: optimize the original objective from that BFS. Uses exact rational arithmetic (Python's Fraction) — results shown as exact fractions.

When to use it

  • Your LP has ≥ or = constraints.
  • You need exact fractional results (no floating-point rounding).
  • You want complete tableau detail for both phases.

System limits

Variables
Up to 8
Constraints
Up to 12
Types
≤, ≥ and = (any mix)
Arithmetic
Exact (Fraction class)

How to enter data

1

Select objective and set variables (1–8) / constraints (1–12).

2

Enter objective function coefficients.

3

For each constraint: coefficients, type (≤, ≥ or =), and RHS.

4

Click Solve.

Fractions accepted in any field: 3/4, -1/2

Special cases

Infeasible

Phase I ends with an artificial variable > 0 in basis. App reports "No feasible solution."

Artificial at zero in basis

Degeneracy at end of Phase I. Solver handles it automatically before Phase II.

Unbounded

Detected in Phase II the same way as standard Simplex.

Quick example

🧪 Example
Minimize  Z = 2X1 + 3X2
Subject to:
  X1 + X2  ≥ 4
  X1 + 3X2 = 6
  X1, X2 ≥ 0

➜ Variables: 2 · Constraints: 2 (one ≥, one =)
✔ Expected: Z* = 7  at  (3, 1)
Ⓜ️
Section 4

Big-M Method

What it is

Alternative to Two-Phase: adds a large penalty coefficient M to artificial variables directly in the objective function. The app uses symbolic M (shown as a + b·M) so tableau entries are exact. Includes a plain-text auto-parser for problem input.

How to enter data

Option A — Manual form: same as Two-Phase.

Option B — Text parser:

Max Z = 3x1 + 5x2
s.t.
x1 + x2 <= 4
x1 + 3x2 >= 6
x1, x2 >= 0

Recognized keywords: Max, Min, Maximize, Minimize, s.t., <=, >=, =.

Quick example

🧪 Example
Maximize  Z = 3X1 + 2X2
Subject to:
  X1 + X2 = 4
  X1      ≥ 1
  X2      ≥ 1

✔ Expected: Z* = 11  at  (3, 1)

Section 5

MOD / MODI Method (Transportation)

What it is

The Modified Distribution Method (MODI) optimizes Transportation Problems. It computes dual multipliers u_i and v_j, evaluates improvement indices δ_ij = c_ij − u_i − v_j for non-basic cells, and traces stepping-stone cycles when δ_ij < 0. Includes automatic balancing.

System limits

Max matrix size
10 sources × 10 destinations
Balancing
Automatic (dummy row/column)

How to enter data

1

Set the number of sources (m) and destinations (n).

2

Enter supply vector and demand vector.

3

Fill in the cost matrix C (m × n).

4

Click Solve.

Special cases

Degeneracy

Basic cells < m+n−1. Solver adds an ε allocation to restore a non-degenerate basis.

Multiple optima

Some δ_ij = 0 in final tableau. Alternative optimal plans exist at the same cost.

Quick example

🧪 Example
2 Sources, 3 Destinations
Costs:
       D1  D2  D3
  S1 [  2   3   1 ]
  S2 [  5   4   8 ]
Supply: [30, 40]  |  Demand: [20, 30, 20]
(Balanced: Σsupply = 70 = Σdemand)

Section 6

Vogel's Method (Transportation)

What it is

Vogel's Approximation Method (VAM) finds a high-quality Initial Basic Feasible Solution (IBFS) for Transportation Problems using penalty-based allocation. At each step, it allocates to the cheapest cell in the row/column with the largest penalty. The app also runs a u-v optimality check after completing the IBFS.

When to use it

  • To get a good starting solution before applying MODI.
  • When Northwest Corner gives a poor initial solution.
  • The u-v check may confirm the Vogel solution is already optimal.

System limits

Max matrix size
10 × 10
u-v optimality check
Included automatically

What the result displays

  • Row and column penalties at each iteration.
  • Allocation made per step (cell chosen, quantity assigned).
  • Final IBFS allocation matrix and total cost.
  • u-v check: if all δ_ij ≥ 0 → "Vogel solution is OPTIMAL"; otherwise → "Apply MODI."

Quick example

🧪 Example
2 Sources, 3 Destinations
Costs:
       D1  D2  D3
  S1 [  2   3   1 ]
  S2 [  5   4   8 ]
Supply: [30, 40]  |  Demand: [20, 30, 20]

Penalty col D3 = 8−1 = 7  → First allocation: S1→D3

Section 7

Minimax Regression (Simplex)

What it is

Chebyshev (L∞) regression fits a line ŷ = a + bx to data by minimizing the maximum absolute error across all points — not the sum of squares. The problem is reformulated as an LP and solved with the Two-Phase simplex method with full tableau display.

When to use it

  • Worst-case error matters more than average error.
  • No single point should deviate by more than a uniform bound.
  • As a teaching exercise: connecting LP to statistical fitting.

System limits

Data points
Min 3, max 12 (x, y) pairs
Coordinate range
−1 000 000 to +1 000 000

How to enter data

1

Set the number of data points (3–12).

2

For each point enter the x value and the y value.

3

Click Solve. Points do not need to be sorted by x.

What the result displays

  • Fitted line parameters: â (intercept) and b̂ (slope).
  • Z* = minimized maximum absolute error.
  • Residuals table: y_i, ŷ_i, |error_i| for each point.
  • Complete Phase I and Phase II tableaux.

Quick example

🧪 Example
Points: (1, 1), (2, 3), (3, 2), (4, 5)

➜ n=4, enter the 4 (x, y) pairs
✔ Result: â and b̂ such that max|residual| is minimized
